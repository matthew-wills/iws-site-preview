What IWS does, stage by stage

IWS holds the whole investigation in one record: the checklist, the evidence, the interviews, the timeline, the AcciMap, the tests and the reports, in a single investigation file, with an optional attachments folder beside it, on the drive you choose. Each stage below works on that same record.

EvidenceAnalysisAssessmentReportingAround the investigation
1Evidence

Capture each item once, and link it to everything it supports

Paste a screenshot or text, or drop in a file. Each item records where it came from and which objects on the AcciMap rest on it, so if a source proves unreliable, what needs revisiting is already listed.

One item, everything it supports

The Tarlton Springs wildlife sighting log was captured once. Its form lists the six AcciMap objects and the timeline event that rest on it, and each line opens that object.

From an object's own form, link an item already in the register and it joins the list. The item is never copied, so a correction made once is made everywhere.

Each item also carries a caption, why it matters, a category, a reference and a short summary for the report.

Interviews

Import a Teams transcript and give each speaker a role. Names stay with the transcript; the record and the report see only the roles.

2Analysis

An AcciMap that evolves with your investigation

A flexible canvas that puts the investigator in control. Move objects, resize lanes and arrange connections as the analysis develops, without rigid layouts. Start with the critical event, then add every event and condition that might have played a part, including the hypotheses you expect to fail. As hypotheses are tested, the map shows where the analysis stands.

You decide the layout

  • Place, move and resize objects wherever the analysis needs them. Dragging an object into another lane changes its level.
  • Drag a lane's lower edge to give it more or less room. The lanes below move with it, and so do the objects below that edge.
  • Draw an arrow by dragging from one object to another.
  • Pan by dragging or scrolling, zoom with Ctrl and the wheel or the zoom control, fit the whole map to the window, and use the minimap on a larger investigation.
  • Select several objects at once, duplicate, nudge with the arrow keys, and undo or redo. Snap to a grid when you want it.
  • From the evidence register, the log, the to-do list or the report, jump straight to the object on the map.

The map reflects the assessments

Each object's look follows the results recorded in its form, so the map shows what has been tested, what passed and what was excluded.

  • HypothesisDashed border: Existence not yet passed. Untested, inconclusive or short of evidence.
  • Safety factorSolid border: Existence passed, Influence still to settle.
  • ContributingBlue: passed Existence and Influence.
  • Other factorOrange: increased risk without influencing this occurrence.
  • Reduced riskPale green: marked by the investigator as reducing risk.
  • ExcludedStruck through: excluded, and kept on the map.
  • Critical eventRed: the critical event.
  • Solid green arrow: the object it leaves has passed Existence and Influence. Grey and dashed until then.

A colour or a solid arrow records the investigator's assessment against the chosen standard of proof. It is not proof of a cause, and a green arrow says nothing on its own about the object it points to.

See what still needs attention

  • Amber dot: not yet finalised
  • Green dot: finalised

Each object shows its finalisation status directly on the AcciMap, making it easier to identify work that remains open without examining every assessment. The dot records whether the investigator has marked their work on that object as finalised, independently of the assessment outcome.

3Assessment

Test each object against the evidence

  • Existence, for every object. Did this event or condition actually exist or occur? A fail excludes the hypothesis, which stays on the map, struck through.
  • Influence, once it exists. Did it influence this occurrence? A pass makes an increased-risk object a contributing factor.
  • Importance, only where Influence fails. Is it still important enough to address? A pass makes it a finding in its own right. Failing both excludes it.
  • A probability and its term. For each result you record how likely it is, and IWS states it as a term from a ten-term scale: 70 per cent reads as “likely”. Where the evidence cuts both ways, record the argument for, the argument against and your reasoning.
  • The standard of proof sets the verdict. At or above it a test reads Pass; otherwise, at or below its mirror it reads Fail, and in between Inconclusive. It is 70 per cent unless you change it in Settings, from 50 to 95 per cent.

4Reporting

The tables and reports come from the same record

The Evidence and Argument Tables are generated directly from the assessments recorded against AcciMap objects. Investigation reports and executive briefings draw on the same record, keeping the evidence, reasoning and reporting connected.

  • The final report also comes in ATSB-, NTSB- and AAIB-inspired layouts, each following that body's published report structure. They are not produced, reviewed or endorsed by those organisations.
  • With Professional, reports are written to Word, on your own Word template if you have one.
  • AI drafting is optional, also with Professional. A draft is written from the record, and you decide what stays. How AI drafting works and where data goes

Around the investigation

  • Dashboard

    The checklist, one to-do list fed from the checklist and from objects on the map, and the distribution list that prints at the foot of every report.

  • Log

    Your running sheet, plus entries the application adds when a decision is made: a checklist answer, a test result, a finalised interview, a draft or an export.

  • One portable file

    No account and no database. The investigation is one .sfm file in plain JSON, with pasted images and captured files held inside it as text, so it can be read without IWS. The one exception is opt-in: a setting that keeps large dropped files in an attachments folder beside it.

  • Shared-folder protection

    Before each save, IWS checks whether the file has changed on disk since it was last opened or saved here. If it has, the save is held and you choose: reload theirs, save yours as a copy, or overwrite. Nothing is merged. While the file is open, a lock file beside it tells anyone else who opens it that it is in use.
